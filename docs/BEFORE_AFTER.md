# Failure by failure: before and after

Evidence classes
- BASELINE: simulated replay of the reported bad call (`results/BASELINE.md`). Not a real call.
- OFFLINE EVAL: the real rules run against a stub model (`results/evals.json`). Proves the safeguard holds. Does not prove model wording or voice latency.
- SIMULATED CALLER: a scripted synthetic caller joins the deployed service over WebRTC and speaks with a synthetic voice (`scripts/sim_call.py`). Real STT, model, TTS and backend. Not a phone call, not production, no real patients.
- PHONE: measured on a real phone call to the test number (`results/phone_test_calls.json`). Four calls so far (1 earlier, 3 in `results/real_test_calls_batch3.json`). Earlier calls from the same phone dropped after 48 to 93 seconds and the cause is not found, so one good call does not prove stability.

Real test calls (6 by the builder, 3 browser and 3 phone, release 1.0.5, synthetic patients, `results/real_test_calls_batch3.json`): all 6 ended after the goodbye; bookings made once per patient (1, 3, 1, 3) with 0 duplicate keys in the database; 0 false "booked" claims; callback reference saved; human transfer was not tested. Reply latency median 1.9s, p95 2.78s, max 3.92s over 43 turns (phone median 1.94s, browser 1.86s; working target 2.0s met, 1.5s not). One phone call needed three name lookups before the patient was found; the cause is not confirmed because the logs do not show what the speech-to-text heard. The caller is a non-native English speaker, so native-speaker results are not measured. Line type (browser or phone) is inferred from call order.

Still open, stated plainly: reply latency is above the 1.5s target in both simulated runs and the one phone call; phone-call stability is unproven (1 good call, 3 earlier drops, cause unknown); human transfer is not tested on a real line.


Found on the real phone calls (not in the original task): the larger-model route failed on every turn and was silently answered by the small model. Cause: the request sent thinking disabled, which Sonnet 5.5 rejects with a 400 error that asks for between_tools; Haiku 5.5 accepts disabled. Fix: the thinking field is chosen per model (`thinking_arg` in `ava/voice/agent.py`), a model that errors now writes an `llm_unavailable` event to the call log, and one offline test checks the field per model. Checked against the live API for both models (one short request each, no call). Not yet measured on a phone call, so the cost and latency of real larger-model turns are still unknown.
