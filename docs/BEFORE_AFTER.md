# Failure by failure: before and after

Evidence classes
- BASELINE: simulated replay of the reported bad call (`results/BASELINE.md`). Not a real call.
- OFFLINE EVAL: the real rules run against a stub model (`results/evals.json`). Proves the safeguard holds. Does not prove model wording or voice latency.
- SIMULATED CALLER: a scripted synthetic caller joins the deployed service over WebRTC and speaks with a synthetic voice (`scripts/sim_call.py`). Real STT, model, TTS and backend. Not a phone call, not production, no real patients.
- PHONE: measured on a real phone call to the test number (`results/phone_test_calls.json`). One call so far. Earlier calls from the same phone dropped after 48 to 93 seconds and the cause is not found, so one good call does not prove stability.

After: 2 simulated-caller calls (one before, one in the final batch), each closed itself after two reprompts (`results/silence_before_after.json`, `results/final_batch_sim_release_1.0.5.json`). The fix is not yet confirmed on a real phone call.

Final clean batch (release 1.0.5, simulated caller, after the deployment settled): 5 of 5 simple bookings booked once each with 0 duplicates and 0 false "booked" claims, 3 of 3 provider answers matched the knowledge base, 1 silent call closed by the agent. Two earlier calls were cut off during a deploy and are excluded; the cause is likely the redeploy but is not proven. Deploys are now limited by watch paths and the worker has a 300s draining window (`docs/RUNBOOK.md`); a call during a real deploy has not been tested. File: `results/final_batch_sim_release_1.0.5.json`.

Callback requests now return a spoken reference (for example CB48291) that is stored with the callback note; the reference is read out only when the callback was actually saved (offline checks, not yet confirmed on a live call).

Still open, stated plainly: reply latency is above the 1.5s target in both simulated runs and the one phone call; phone-call stability is unproven (1 good call, 3 earlier drops, cause unknown); human transfer is not tested on a real line.
